# 🏠 智居 · 智能家居场景联动与设备健康看板

基于 **Vue 3 + Vite + Pinia（前端）+ Express + SQLite（后端）** 的智能家居演示看板。纯 mock 设备数据，无真实硬件接入。

## 技术栈

- 前端：Vue 3 + Vite + Pinia
- 后端：Node.js 内置 `node:sqlite` + Express，REST API
- 数据库：`server/home.db`（SQLite，首次启动自动建表 + 预置演示数据）

## 运行

```bash
npm install
npm run dev
```

前端 http://localhost:5190（Vite 已代理 `/api` 到 http://localhost:4120）。
需 Node ≥ 22.13。

## 功能

- **健康看板**：设备在线/异常统计、房间分布、设备类型、告警中心（低电量/信号弱/离线/能耗尖峰/定额预警与超标）、全屋 24h 能耗趋势、定额状态
- **设备管理**：按房间/类型/状态筛选，添加/删除设备，开关切换，功率编辑、电量/信号条
- **场景联动**：可视化动作编排（设备→动作），创建/启用停用/触发场景，触发后写入日志并联动开关真实设备状态
- **能耗统计**：按设备开关/功率变化分段累计用电（功率×时长），近24小时总量、按房间分布、设备用电排行、实时功率、节能提示、周期定额执行进度与超标标记；已删除设备历史保留并标记
- **定额预警**：按房间/设备配置日/周/月用电额度（kWh）与预警线（默认 80%）；持续按分段用电聚合本周期用量（在跑段跨周期按重叠时长分摊），达线触发预警/超标告警；导航角标 + toast + 日志实时通知；告警支持填写处理说明闭环、可重开；额度/预警线调整强制填写原因并保留完整调整历史；删除定额/设备后历史告警与调整记录保留
- **日志时间线**：所有操作的实时记录

## 分段用电模型

- `energy_segments`：每台开启运行中设备的段首（设备标识 + 名称/房间/功率快照 + 起始时间）。开关切换、功率编辑、改名、换房时旧段立即结落，再按当前状态开新段
- `energy_records`：结落的分段明细，按 `device_id` 稳定归属（删除设备不级联），含完整 ISO 起止时间、产生时的名称/房间快照与 kWh；服务端每 30s 模拟运行节拍结段续开，明细保留 7 天
- 旧版 `energy(device_name,room,kwh,hour)` 数据首次启动自动迁移：名称唯一命中的绑定设备标识，重名/设备已删除的不猜绑，保留名称房间快照（排行中标记「旧记录」）
- 看板 24h 趋势、能耗排行与尖峰告警均读自分段记录；前端 20s 自动刷新

## 能耗定额与超标预警闭环

- `energy_quotas`：定额配置，按 `scope(room/device) + 目标 + period(daily/weekly/monthly)` 唯一；周期窗口按本地时间（日=今日 0 点、周=本周一 0 点、月=1 日 0 点）；可停用、可调预警比例
- 用量聚合：`energy_records` 中 `end_time` 落在周期窗口内的段全额计入 + `energy_segments` 在跑段按与窗口重叠时长折算（段首在窗口前的跨周期部分不重复计入）；房间按记录中的房间快照聚合，设备按稳定 `device_id`
- `quota_alerts`：达 `limit×warn_ratio` 生成预警、达 `limit` 生成超标；同一「定额 + 周期起点 + 级别」只告警一次，处理后不重报，周期滚动后自动开新一轮；保留 `open/handled` 状态、处理备注与处理时间，可重开；告警文案与目标名按产生时快照保存
- `quota_adjustments`：额度或预警线的每次调整强制填写原因，留存新旧值、原因、操作人与时间
- 通知通道：`device_logs` 时间线、导航「定额预警」角标（未处理数）、新告警 toast、健康看板告警中心（超标 error 红、预警 warn 黄）
- 删除定额或设备不级联历史：告警/调整记录保留可追溯；已删除设备的定额标记「设备已删除」，本周期历史用量仍正常聚合
- 服务端 30s 周期评估 + 前端拉取/操作时兜底评估；首次启动预置三条演示定额（设备超标、房间预警、房间正常）及一条已闭环的上周超标→复核上调历史

## 数据库表
